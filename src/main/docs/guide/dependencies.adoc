== Compiler plugin

`micronaut-inject-scala_3.10.0` runs inside the Scala compiler. It bundles the
Micronaut and ASM classes it needs because the compiler loads plugins in an
isolated classloader.

Most bundled dependencies are omitted from the published POM to avoid resolving
them again as separate plugin jars. Keep the compiler plugin on the compiler
plugin configuration: putting it on an application's runtime classpath can
introduce conflicting copies of Micronaut and ASM.

== Runtime support

`micronaut-runtime-scala` supplies converters for Scala collections and `Option`.
It also provides serializers and deserializers when Micronaut Serialization is
present. Include it at runtime when your application uses these features.

This artifact has no compiler-version suffix because it does not run inside the
compiler.

== Compile-time visitors

The Scala plugin discovers `TypeElementVisitor` implementations through
`ServiceLoader` on the compilation classpath. Processors from other Micronaut
modules, such as validation or Data, must therefore be compile-time dependencies
of the module containing your Scala sources.

Adding a processor only to Gradle's `annotationProcessor` configuration makes it
available to `javac`, not to the Scala plugin. Use `compileOnly` for a processor
needed by Scala sources.

Visitors load their dependencies from the compilation classpath in preference
to the compiler process's own libraries. They share the JDK, Scala compiler
classes and classes bundled with the plugin. This keeps libraries used by a
visitor, such as Jackson or SnakeYAML, separate from versions used by the build
tool's compiler infrastructure.

== Versions

The suffix identifies the full Scala compiler version. For example,
`micronaut-inject-scala_3.10.0` is published; `micronaut-inject-scala_3` is not.
See <<introduction, Supported versions>> for the available compiler variants.

The Micronaut Scala release version is independent of the Micronaut Core version.
