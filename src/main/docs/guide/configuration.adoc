Options are passed to the plugin with the standard Scala compiler-plugin syntax:

----
-P:micronaut-scala:<key>=<value>
----

An option without `=` has the value `"true"`.

== Available options

The plugin passes options to `VisitorContext.getOptions()`. Micronaut processing
code and any `TypeElementVisitor` on the compilation classpath can read them,
so visitors may accept additional keys beyond those listed here.

The table lists the well-known keys in the plugin's help. Their effect depends
on the processing code that reads them. Use `-P:micronaut-scala:help` to print
the help.

|===
|Key |Meaning

|`micronaut.processing.incremental`
|Incremental processing hint (`true` or `false`). This does not make build tools
track generated bean definitions; see <<limitations, Limitations>>.

|`micronaut.processing.group`
|The Maven group of the module being compiled.

|`micronaut.processing.module`
|The name of the module being compiled.

|`micronaut.processing.project.dir`
|The project directory passed to processing code.

|`micronaut.processing.annotations`
|Comma-separated package prefixes for processors that support annotation filtering.

|`micronaut.processing.use.context.classloader`
|Micronaut's context-classloader switch. The Scala integration enables context
classloader lookup internally while processing.
|===

== Setting options

[source,kotlin]
----
tasks.withType<ScalaCompile>().configureEach {
    scalaCompileOptions.additionalParameters.addAll(
        listOf(
            "-J--add-modules=java.compiler",
            "-P:micronaut-scala:micronaut.processing.group=com.example",
            "-P:micronaut-scala:micronaut.processing.module=app"
        )
    )
}
----

NOTE: The plugin accepts unknown keys. Check the spelling if an option has no
effect; a typo does not cause a compilation error.
