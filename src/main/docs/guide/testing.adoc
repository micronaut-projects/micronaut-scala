`micronaut-inject-scala-test_<scala version>` provides a harness for compiling
Scala sources in-process and inspecting the resulting elements, bean definitions
and introspections. It can also start an `ApplicationContext` from the compiled
classes.

Use this harness when developing the Scala integration or a compile-time visitor.
Application tests can use the normal Micronaut testing APIs without it.

== Add the harness

dependency:io.micronaut.scala:micronaut-inject-scala-test_3.9.0[scope="testImplementation"]

The artifact suffix must match the full Scala compiler version. See
<<dependencies, Artifacts and Dependencies>>.

== Set the system properties

The harness invokes the Scala compiler directly. Supply both of these properties
so it can locate the plugin and resolve the compiled source's dependencies:

|===
|Property |Value

|`micronaut.scala.plugin.jar`
|Absolute path to the compiler plugin jar.

|`micronaut.scala.test.classpath`
|Classpath for the compiled sources, usually the test runtime classpath.
|===

For a Gradle test task, with `pluginJar` referring to the built plugin jar:

[source,kotlin]
----
tasks.withType<Test>().configureEach {
    doFirst {
        systemProperty("micronaut.scala.plugin.jar", pluginJar.absolutePath)
        systemProperty(
            "micronaut.scala.test.classpath",
            sourceSets.test.get().runtimeClasspath.asPath
        )
    }
}
----

Using `doFirst` defers classpath resolution until the test task runs. The harness
reports an error if either required property is missing.

== Compile and inspect sources

`AbstractScalaTypeElementSpec` provides these helpers:

* `buildClassElement(name, source)` compiles source and returns its `ClassElement`.
* `buildBeanDefinition(name, source)` compiles and loads a bean definition.
* `buildBeanIntrospection(name, source)` compiles and loads an introspection.
* `buildContext(source, properties, includeAllBeans)` compiles source and starts
  an `ApplicationContext`.
* `buildClassLoader(name, source)` compiles source and returns a classloader for
  the output.

A test can install a visitor for a compilation to capture the `VisitorContext`
and inspect the elements produced by the compiler.
