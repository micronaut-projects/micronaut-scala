The compiler plugin makes Scaladoc comments available to Micronaut's
compile-time visitors. Those visitors can use the comments for descriptions in
configuration metadata, OpenAPI definitions and JSON schemas.

== Write Scaladoc comments

No compiler flag or plugin option is needed. Use `/** ... */` comments above the
declarations you want to document; ordinary `//` comments are not included.

For a constructor property, write a class-level `@param` tag:

snippet::io.micronaut.docs.documentation.MailerConfig[source=main,language=scala,tags=clazz]

The generated configuration metadata includes the class description and each
parameter's description:

[source,json]
----
{
  "groups": [
    { "name": "mailer",
      "type": "io.micronaut.docs.documentation.MailerConfig",
      "description": "Configures the outbound mailer." }
  ],
  "properties": [
    { "name": "mailer.host", "type": "java.lang.String",
      "description": "the SMTP host to connect to" },
    { "name": "mailer.port", "type": "int",
      "description": "the port the SMTP host listens on" }
  ]
}
----

For a property declared in the class body, put the comment directly above it:

[source,scala]
----
@ConfigurationProperties("mailer")
class MailerConfig:
  /** How many messages to send at once. */
  var batchSize: Int = 10
----

Place the main description before any block tags such as `@param`, `@return`
or `@throws`. The description ends at the first block tag.

== Where descriptions appear

Configuration metadata:: Compiling `@ConfigurationProperties` classes generates
`META-INF/spring-configuration-metadata.json`. The class comment describes the
configuration group, and property comments or `@param` tags describe its keys.
IDEs can display these descriptions during configuration completion.

OpenAPI:: Add `micronaut-openapi` to the compilation classpath to generate an
OpenAPI definition. Its visitor can use comments on controller methods and
exposed types for operation and schema descriptions. Explicit descriptions in
annotations such as `@Schema` take precedence.

JSON schema:: A JSON schema generator can read the same documentation through
Micronaut's element API. Add the generator required by your application to the
compilation classpath.

== Comments from dependencies

The plugin reads comments from the sources being compiled. Class files from
another module or library do not retain Scaladoc, so those types do not provide
comments through this mechanism. If needed, document the member that exposes
the dependency type in your own sources.

`GuideExamplesSpec` checks the generated metadata for the `MailerConfig`
example. OpenAPI examples and generation tests are in `test-suite-scala-openapi`.
