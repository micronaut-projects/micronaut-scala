Micronaut works well with Scala constructor parameters, case classes and
traits. The examples below show how to use those features for beans and
configuration, with a few details to keep in mind when using Java APIs.

== Prefer constructor injection

Declare dependencies as constructor parameters so they are available throughout
the class body, including when initialising a `val`:

snippet::io.micronaut.docs.idiomatic.ReportService[source=main,language=scala,tags=constructor]

With field injection, a declaration such as `@Inject var clock: Clock = null`
remains null until injection runs. Constructor injection avoids that intermediate
state and lets unit tests construct the class directly with test dependencies.

== Case classes for configuration

A case class makes a convenient immutable configuration bean:

snippet::io.micronaut.docs.idiomatic.ServerConfig[source=main,language=scala,tags=caseClassConfig]

Default parameter values:: The constructor default is used when the property is
absent. Here, `host` defaults to `localhost`; `server.host` overrides it.
`Option[String]`:: An optional property binds to `None` when absent.
`List[String]`:: A list-valued property binds to a Scala list, with element
conversion. Scala `Seq`, `Set` and `Map` are also supported.
`case`:: Generated equality and `toString` methods help when comparing
configuration values in tests or inspecting them while debugging.

Use class-level Scaladoc `@param` tags to document constructor properties in
generated configuration metadata. See <<documentation, Documentation in Generated Files>>.

NOTE: Binding `Option` and Scala collections requires `micronaut-runtime-scala`
on the runtime classpath.

=== Repeated configuration

Use `@EachProperty` when the same configuration structure appears under several
names, such as a set of data sources. `@Parameter` receives each entry's name:

snippet::io.micronaut.docs.idiomatic.ServerConfig[source=main,language=scala,tags=eachProperty]

Configuring `datasources.one.url` and `datasources.two.url` creates two
`DataSourceConfig` beans. Inject one by name with `@Named`, or inject a
collection to receive them all.

=== Enums in configuration

For an enum bound from a configuration string, extend `java.lang.Enum`:

snippet::io.micronaut.docs.idiomatic.Mode[source=main,language=scala,tags=enum]

Configuration binding uses Micronaut's Java enum converter. A plain Scala enum
does not extend `java.lang.Enum`, so this conversion fails. The example above
supports both a configured value and the constructor default when no value is
set. JSON serialization has separate support for plain Scala enums; see
<<serialization, Serialization>>.

== Use traits for replaceable dependencies

A trait lets a bean depend on an interface while Micronaut supplies an
implementation:

snippet::io.micronaut.docs.idiomatic.Notifier[source=main,language=scala,tags=trait]

snippet::io.micronaut.docs.idiomatic.Notifier[source=main,language=scala,tags=implementations]

When several beans implement the trait, a collection parameter receives all of
them:

snippet::io.micronaut.docs.idiomatic.Notifier[source=main,language=scala,tags=collection]

If a dependency is optional, declare an `Option` parameter. It receives `None`
when no matching bean exists:

snippet::io.micronaut.docs.idiomatic.Notifier[source=main,language=scala,tags=optional]

To select one of several implementations, use a qualifier such as `@Named` at
the injection point. This also lets a test supply a different implementation
without changing the consuming bean.

Traits can also declare abstract methods implemented by introduction advice,
as described in <<concepts, Micronaut for Scala Developers>>.

== Factories for types you do not own

Use `@Factory` to create beans from library types or to centralise construction
logic. Each method annotated with a scope supplies a bean of its return type:

snippet::io.micronaut.docs.idiomatic.ReportService[source=main,language=scala,tags=factory]

The `Clock` returned by this factory can be injected into `ReportService`.

== Scala objects as beans

A Scala `object` can be annotated with `@Singleton`:

snippet::io.micronaut.docs.idiomatic.Notifier[source=main,language=scala,tags=objectBean]

In this example, the injection point uses `HouseStyle.type`, the singleton type
of that specific object. A test double cannot have the same singleton type.
For behaviour you may want to replace, prefer a class injected through a trait.
Objects remain useful for constants and pure helper functions.

== AOP and annotation rules

AOP proxies extend your bean class and override advised methods. Keep advised
classes and methods non-final so the compiler can generate those overrides.

Java annotation arguments also follow Scala's rules: use explicit arrays for
array-valued members and name annotation arguments. See <<annotations, Annotations>>
for examples.

These examples are compiled and run by `GuideExamplesSpec` in `test-suite-scala`.
