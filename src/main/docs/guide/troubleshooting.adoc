== No bean definitions are generated

If compilation succeeds but produces no `$*$Definition` classes, check that the
plugin is registered with the Scala compiler. Use `scalaCompilerPlugins`,
`addCompilerPlugin`, `scalacPluginIvyDeps` or Maven's `compilerPlugins`, as shown
in <<buildTools, Build Tools>>. An ordinary application dependency does not load
the plugin.

Run the compiler with `-Xplugin-list` to check which plugins loaded. Also check
that the source declares a bean, for example with `@Singleton`.

== `NoClassDefFoundError` inside the compiler

----
java.lang.NoClassDefFoundError: io/micronaut/inject/processing/ProcessingException
----

Check that you are using the published compiler plugin jar with its bundled
dependencies. A jar containing only this project's classes lacks the Micronaut
and ASM classes needed during processing.

The Scala compiler loads a plugin from its `-Xplugin` path in a separate
classloader. In Gradle, each resolved plugin jar gets its own `-Xplugin`
argument, so adding the missing dependencies as separate plugin entries does
not make them visible to the plugin. Use the complete bundled jar.

== `Missing plugin.properties` warnings

----
warning: Missing plugin.properties in <some-jar>
----

A jar passed to `-Xplugin` has no plugin descriptor. This can happen when the
build tool resolves transitive dependencies into the compiler plugin
configuration. The compiler skips those jars.

Check the resolved plugin configuration. The Micronaut Scala plugin jar itself
must contain `plugin.properties` at its root.

== Errors mentioning `javax.lang.model`

Make the `java.compiler` module available in the compiler process:

----
-J--add-modules=java.compiler
----

See <<buildTools, Build Tools>> for the compiler configuration examples.

== `Could not find ..._3:<version>`

Use the full Scala compiler version in the plugin artifact name. For example,
this project publishes `micronaut-inject-scala_3.9.0`, not
`micronaut-inject-scala_3`.

With cross-version notation, use `CrossVersion.full` in sbt or `:::` in Mill.
With explicit coordinates, write the full suffix in the artifact ID.

== Scala collections or `Option` fail to bind

If configuration binding or injection involving a Scala collection or `Option`
fails at runtime, check that `micronaut-runtime-scala` is on the runtime
classpath. Its converters are separate from the compiler plugin. Also check
that the configured values can be converted to the declared element type.

See <<dependencies, Artifacts and Dependencies>>.

== `The version of 'scala-library' was changed while using the default Zinc version`

----
Version 3.9.0 is not compatible with org.scala-sbt:zinc_2.13:1.12.0
----

Check whether a dependency-resolution rule is applying your Scala 3 version to
Gradle's `zinc` configuration. Zinc needs its own Scala 2.13 `scala-library` and
`scala-reflect` dependencies. Exempt that configuration from application Scala
version pinning.

== A deleted bean is still available

Run a clean build after deleting or renaming a bean. Build tools do not track
the generated bean definition as an output of its source, so an incremental
build can leave the definition behind. See <<limitations, Limitations>>.

== A plugin option has no effect

The plugin passes `-P:micronaut-scala:` options to
`VisitorContext.getOptions()` and accepts unknown keys. Check the spelling and
confirm that the visitor using the option is on the compilation classpath. See
<<configuration, Configuration Options>>.
