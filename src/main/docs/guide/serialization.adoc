https://micronaut-projects.github.io/micronaut-serde/latest/guide/[Micronaut Serialization]

This example writes as `{"sku":"sku-1","quantity":2}`. Deserialization calls the

Add the serialization implementation and Scala runtime support:

dependency:io.micronaut.serde:micronaut-serde-jackson[]

dependency:io.micronaut.scala:micronaut-runtime-scala[scope="runtimeOnly"]

The runtime module supplies serializers and deserializers for Scala `Option`,
collections and enums.

== Option

`Some(value)` writes the contained value without a wrapper. With the default
inclusion settings, a property containing `None` is omitted. The serializer
reports an empty option as absent; if it is written explicitly, it writes as
JSON `null`.

Give optional constructor parameters a default of `None`:

[source,scala]
----
notes: Option[String] = None
----

When the JSON omits the property, Micronaut Serialization uses the constructor
default. Without that default, an omitted `Option` property currently receives
`null`. An explicit JSON `null`, however, deserializes to `None` even without a
constructor default.

This missing-property behaviour is covered by the serialization tests and is
tracked in
https://github.com/micronaut-projects/micronaut-serialization/issues/1416[micronaut-serialization#1416].

Defaults also work for collections. For example,
`labels: Map[String, String] = Map.empty` gives an omitted `labels` property an
empty map.

== Collections

Scala collections such as `List`, `Seq`, `Set`, `Vector` and `IndexedSeq` write
as JSON arrays. Maps write as JSON objects, with their keys represented as
strings. During deserialization, elements, keys and values are read using the
declared type arguments. For example, `List[Line]` uses the `Line` deserializer
for each element, and `Map[Int, String]` converts JSON property names to integers.

The result matches the declared collection type: `Vector[Int]` produces a
`Vector`, while `Seq[String]` produces a compatible sequence. Supported mutable
collection interfaces include `mutable.Seq`, `mutable.Set`, `mutable.Buffer`,
`mutable.IndexedSeq` and `mutable.Map`.

Deserialization uses the collection converters registered by
`micronaut-runtime-scala`. A custom collection type needs a converter that can
produce that type.

== Scala 3 enums

An enum with parameterless cases writes as its case name:

snippet::io.micronaut.docs.serde.Status[project=test-suite-scala-serde,source=main,language=scala,tags=enum]

Deserialization looks up the name using the compiler-generated `valueOf` method.
Unknown names cause a deserialization error. Serialization uses the case name
even if the enum overrides `toString`.

The enum does not need its own `@Serdeable` annotation. Enums with parameterised
cases do not have the required `valueOf` method and are not supported by this
serializer. Model those values with a suitably configured serializable hierarchy
or provide a custom serializer.

== Other serialization features

Micronaut Serialization's documentation covers supported Jackson annotations,
naming strategies, views and custom serializers. Use
`@Serdeable.Serializable` for serialization only and `@Serdeable.Deserializable`
for deserialization only. See <<annotations, Annotations>> for Scala's rules
when supplying Java annotation arguments.

The examples in this chapter are compiled and tested with an `ObjectMapper` in
`test-suite-scala-serde`.
