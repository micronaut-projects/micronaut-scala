Known gaps, with the reason for each. Anything not listed here is either supported
or has not been established either way.

== Scala shapes not modelled

=== Generic detail on classpath types

Two places report less detail than the Java and Kotlin integrations, without
reporting anything wrong:

* A type variable of a *classpath* type reports its own type arguments as empty,
  where the other integrations model two levels before collapsing to `Object`.
* A lower-bounded wildcard (`? >: T`) is reported as its upper bound, so
  `List[? >: String]` gives `Object`.

Both erase to a correct JVM type; they simply carry less information than they
could.

== Incremental compilation

Bean definitions are written into the class output directory by the compiler
plugin, not through the compiler's own output mechanism, so the build tool does
not record them as products of the source that produced them.

The visible consequence is that **deleting a bean's source does not remove its bean
definition**. The generated `$Foo$Definition.class` and its
`META-INF/micronaut/io.micronaut.inject.BeanDefinitionReference/` marker both
survive the rebuild, so a deleted bean is still a bean at runtime. The same
applies to a definition left behind by a compilation that later failed.

Run a clean build after deleting or renaming a bean.

NOTE: A partial recompile does *not* lose the definitions of sources it did not
recompile. Each implementation gets its own empty marker file named for the class,
so there is no shared service file for a partial run to truncate.

== Not defects

Listed because they look like gaps and are not:

* **Varargs.** `def f(xs: String*)` compiles to a single method taking
  `scala.collection.immutable.Seq` with `ACC_VARARGS` unset, so the parameter type
  and `isVarArgs() == false` are both accurate.
* **`protected`.** Scala `protected` and `protected[pkg]` compile to public
  members, and the model reports what the bytecode contains.
* **Field visibility.** Every Scala `val` and `var` is a private field behind
  accessors, so queries that select public fields return nothing. The fields are
  present; they are not accessible.
* **Trait parameters, `inline`, and extension methods declared in a class body**
  are all modelled.
