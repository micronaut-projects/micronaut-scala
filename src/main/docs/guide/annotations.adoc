Micronaut uses Java annotations. When applying them in Scala, use explicit
arrays, name the arguments and write repeatable-annotation containers yourself.
These differences matter when adapting examples from Java.

== Array-valued members

Java allows a single value for an array-valued annotation member. Scala requires
an array, even for one element. This does not compile:

[source,scala]
----
@Introspected(accessKind = Introspected.AccessKind.METHOD)   // does not compile
----

....
Found:    (io.micronaut.core.annotation.Introspected.AccessKind.METHOD :
  io.micronaut.core.annotation.Introspected.AccessKind)
Required: Array[io.micronaut.core.annotation.Introspected.AccessKind]
....

Wrap the value in `Array(...)`:

snippet::io.micronaut.docs.annotations.AnnotationExamples[source=main,language=scala,tags=arrayMember]

== Named arguments

Use named arguments for Java annotation members. A positional argument can bind
to the first declared member rather than `value`. For example, `@Min(10)` binds
to the `message` member of `jakarta.validation.constraints.Min` and fails:

[source,scala]
----
def check(@Min(10) size: Int): Int = size   // does not compile
----

....
Found:    (10 : Int)
Required: String
....

Name the member explicitly:

snippet::io.micronaut.docs.annotations.AnnotationExamples[source=main,language=scala,tags=namedMember]

An annotation whose only member is `value` also accepts a positional argument.
Naming it still makes the intent clear.

== Repeatable annotations

Scala does not accept repeated applications of the same annotation. Use the
container annotation declared by Java's `@Repeatable`, with `new` for each entry:

snippet::io.micronaut.docs.annotations.AnnotationExamples[source=main,language=scala,tags=container]

For Micronaut annotations, common pairs are `@Requires` and `@Requirements`,
`@InterceptorBinding` and `@InterceptorBindingDefinitions`, and `@Property` and
`@PropertySource`.

== Declaring an annotation

A Scala annotation extends `scala.annotation.StaticAnnotation` and declares its
members as constructor parameters. Use `@Retention(RetentionPolicy.RUNTIME)`
for Micronaut annotation processing and `@Target` to specify where it applies:

snippet::io.micronaut.docs.annotations.AnnotationExamples[source=main,language=scala,tags=declaring]

If another annotation accepts your annotation type as a `classOf[...]` argument
bounded by `Annotation`, also extend `java.lang.annotation.Annotation` and
implement `annotationType()`, as `Managed` does above. Examples of such arguments
include those of `@InterceptorBean`, `@Type` and `@Introduction(interfaces = ...)`.

== Scala and Java type names

Check which type a short name refers to. Scala's `StringBuilder` is
`scala.collection.mutable.StringBuilder`; use `java.lang.StringBuilder` when a
Java API or injection point needs that type.

Similarly, Scala `Seq`, `List` and `Map` differ from Java collections. The
runtime support converts between supported collection types, but the types are
not interchangeable in method signatures.
