Micronaut's annotations are Java annotations, and Scala applies a Java annotation
by different rules to Java's own. Each difference below is a compile error rather
than a silent change in meaning, so nothing gets past the compiler — but the
message names a type mismatch, not the rule behind it, which is hard to act on if
you are transcribing an example from Micronaut's Java documentation.

== A single value is not an array

Java lets a one-element array member be written without braces. Scala does not:

[source,scala]
----
@Introspected(accessKind = Introspected.AccessKind.METHOD)   // does not compile
----

....
Found:    (io.micronaut.core.annotation.Introspected.AccessKind.METHOD :
  io.micronaut.core.annotation.Introspected.AccessKind)
Required: Array[io.micronaut.core.annotation.Introspected.AccessKind]
....

Wrap it, whether it holds one element or several:

== Name the member

In Java, a single unnamed argument goes to the member called `value`. Scala binds
a positional argument by *declaration order* instead, which is the order the
members appear in the annotation's class file and is rarely the one you want. For
`jakarta.validation.constraints.Min`, whose first declared member is `message`:

[source,scala]
----
def check(@Min(10) size: Int): Int = size   // does not compile
----

....
Found:    (10 : Int)
Required: String
....

The habit that always works is to name every member, even when there is only one:

snippet::io.micronaut.docs.annotations.AnnotationExamples[source=main,language=scala,tags=namedMember]

NOTE: An annotation whose only member is `value` accepts a positional argument,
because declaration order and the `value` convention agree. Relying on that means
the same expression breaks when a member is added ahead of it.

== Repeatable annotations

Scala has no repeatable annotations. Writing one twice is an error, so the
container Java would generate has to be written out, with `new` on each entry:

snippet::io.micronaut.docs.annotations.AnnotationExamples[source=main,language=scala,tags=container]

Micronaut's repeatable annotations each name their container in `@Repeatable` —
`@Requires` uses `@Requirements`, `@InterceptorBinding` uses
`@InterceptorBindingDefinitions`, `@Property` uses `@PropertySource`.

== Declaring an annotation

A Scala annotation extends `scala.annotation.StaticAnnotation`, and its members
are constructor parameters. Give it `@Retention(RetentionPolicy.RUNTIME)` so
Micronaut can read it, and `@Target` to say where it may be written:

snippet::io.micronaut.docs.annotations.AnnotationExamples[source=main,language=scala,tags=declaring]

An annotation used as a `classOf[...]` argument — `@InterceptorBean`, `@Type`,
`@Introduction(interfaces = ...)` — must also extend
`java.lang.annotation.Annotation` and override `annotationType()`, because those
members are declared as `Class[? <: Annotation]`. The `Managed` example above
shows the full form.

== Types that are not the Java type of the same name

`StringBuilder` in Scala is `scala.collection.mutable.StringBuilder`, a different
type from `java.lang.StringBuilder`. An injection point or a bean method that
means the Java one has to say so. The same applies to `Seq`, `List` and `Map`,
which are Scala collections rather than `java.util` ones — both are supported,
and `micronaut-runtime-scala` binds the Scala forms, but they are not
interchangeable at a type level.
