This project publishes a Scala compiler plugin for use by Scala 3 builds.
The plugin must be selected for the exact Scala compiler version used by the
application.

There are two artifacts, and they are not interchangeable:

`micronaut-inject-scala_<scala version>`:: The compiler plugin. It runs inside
the Scala compiler and generates bean definitions. It is crossed with the full
compiler version, and it bundles the Micronaut classes it compiles against, so
it belongs on the compiler plugin configuration and nowhere else.

`micronaut-runtime-scala`:: The application-side support: the converters that
let Micronaut bind Scala collections and `Option`. It is a small ordinary
library, is not crossed with the compiler version, and belongs on the runtime
classpath.

== Gradle

For Scala 3.9.0:

[source,kotlin]
----
scalaCompilerPlugins("io.micronaut.scala:micronaut-inject-scala_3.9.0:1.0.0-SNAPSHOT")
runtimeOnly("io.micronaut.scala:micronaut-runtime-scala:1.0.0-SNAPSHOT")
----

WARNING: Do not put the compiler plugin on the application runtime classpath.
It bundles Micronaut and ASM at their original package paths, so it would place
a second copy of those classes in the running application.

Use a released Micronaut Scala version in published applications. During
development, the repository can be built against the Core SPI branch with
IncludeGit or a local Core checkout:

[source,bash]
----
./gradlew check -Plocal.git.micronaut-core=/path/to/micronaut-core
----

== Maven

Use the full compiler-version artifact ID for the compiler plugin, and the
uncrossed artifact for the runtime support:

[source,xml]
----
<dependency>
  <groupId>io.micronaut.scala</groupId>
  <artifactId>micronaut-inject-scala_3.9.0</artifactId>
  <version>1.0.0-SNAPSHOT</version>
  <scope>provided</scope>
</dependency>
<dependency>
  <groupId>io.micronaut.scala</groupId>
  <artifactId>micronaut-runtime-scala</artifactId>
  <version>1.0.0-SNAPSHOT</version>
  <scope>runtime</scope>
</dependency>
----

== sbt and Mill

sbt builds should use `CrossVersion.full` so the complete Scala compiler
version participates in the artifact coordinate. Mill builds should use the
full-cross `:::` dependency syntax. In both tools, select the integration
version independently from the Scala compiler version.

=== Configuration properties

A `@ConfigurationProperties` class binds its constructor parameters from configuration.
Scala's own types work here, which is what `micronaut-runtime-scala` provides: a
`List[Int]` binds from a list-valued property, and an `Option[String]` binds to `None`
when the property is absent rather than failing the bean.

== Compiler compatibility

Do not replace `_3.9.0` with a binary Scala line suffix. Compiler plugin APIs
can change between compiler releases, so a plugin built for one full compiler
version must not be assumed to work with another. See the
https://docs.scala-lang.org/overviews/plugins/index.html#binary-compatibility-of-compiler-plugins[Scala compiler-plugin binary-compatibility guidance].
