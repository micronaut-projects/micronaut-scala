https://micronaut-projects.github.io/micronaut-data/latest/guide/[Micronaut Data]
generates query metadata at compile time and implements repository methods
through introduction advice. Scala entities can be case classes, and repositories
can be traits or abstract classes.

== Dependencies

Add the Data processor to the compilation classpath of the module containing
your Scala entities and repositories. The Scala plugin discovers its
`TypeElementVisitor` through that classpath:

dependency:io.micronaut.data:micronaut-data-processor[scope="compileOnly"]

WARNING: An `annotationProcessor` dependency alone is insufficient for Scala.
That configuration is used by `javac`. A module with both Java and Scala entities
needs the processor in both configurations.

Without the processor on the Scala compilation classpath, a repository proxy may
still be generated, but calling it can fail with
`Micronaut Data method is missing compilation time query information`.

For JDBC access to the in-memory H2 database used here, add:

dependency:io.micronaut.data:micronaut-data-jdbc[]

dependency:io.micronaut.sql:micronaut-jdbc-hikari[scope="runtimeOnly"]

dependency:com.h2database:h2[scope="runtimeOnly"]

Also add the runtime converters for Scala collection results:

dependency:io.micronaut.scala:micronaut-runtime-scala[scope="runtimeOnly"]

See <<dependencies, Artifacts and Dependencies>> for more about visitor loading.

== Define an entity

Annotate a case class with `@MappedEntity`. Put the property annotations on its
constructor parameters:

snippet::io.micronaut.docs.data.Book[project=test-suite-scala-data,source=main,language=scala,tags=clazz]

The plugin makes those annotations available on the properties Micronaut Data
processes. `@Id` marks the identifier, and `@GeneratedValue` requests a
database-generated value.

The identifier uses Scala `Long`, which maps to Java's primitive `long`. A new
entity starts with `id` set to `0`; the entity returned by `save` contains the
generated identifier.

== Define a repository

Extend `CrudRepository` to inherit the standard persistence operations. Add
methods whose names describe queries:

snippet::io.micronaut.docs.data.BookRepository[project=test-suite-scala-data,source=main,language=scala,tags=clazz]

`findByTitle` finds matching rows, and `countByPagesGreaterThan` counts rows with
a larger page count. The type arguments in `CrudRepository[Book, Long]` tell
Micronaut Data which entity and identifier types the inherited operations use.

The compiler plugin and Data processor generate the proxy and query metadata.
Inject `BookRepository` to use it; you do not need to implement the abstract
methods. Concrete methods on the trait or abstract class retain their own
implementation.

== Scala types in method signatures

`findByTitle` returns a Scala `List[Book]`. At compile time, the plugin identifies
Scala collections as iterable results so Data can process a multi-row query.
At runtime, the Scala converters turn the result collection into the declared
type.

`countByPagesGreaterThan` returns Scala `Long`, represented as a primitive.

For an optional single result, use `java.util.Optional`, as `findFirstByTitle`
does. Micronaut Data currently rejects `scala.Option` for this signature:

----
Unable to implement Repository method: BookRepository.findFirstByTitle(String title).
Query results in a type [Book] whilst method returns an incompatible type: scala.Option
----

To convert the result to Scala `Option`, import `scala.jdk.OptionConverters.*`
and call `.toScala`.

== Configuration and testing

The example repository uses the default data source. Configure an in-memory H2
database with schema creation enabled:

[source,yaml]
----
datasources:
  default:
    url: jdbc:h2:mem:books;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE
    driver-class-name: org.h2.Driver
    username: sa
    password: ""
    schema-generate: CREATE_DROP
    dialect: H2
----

In a test, start an `ApplicationContext` with these properties, retrieve the
repository and call its methods.

The examples are compiled and run against H2 in `test-suite-scala-data`. That
module also compares generated query metadata with an equivalent Java repository.
