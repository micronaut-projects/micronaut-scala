Micronaut provides dependency injection, configuration binding, introspection
and AOP. This chapter introduces those features through Scala examples.

The Scala compiler plugin runs Micronaut's compile-time processing while your
Scala sources are compiled. You use the same Micronaut annotations and runtime
APIs as you would in a Java application.

== Compile-time processing and runtime bean creation

During compilation, the plugin generates a `BeanDefinition` for each bean. It
records how to construct the bean, which dependencies it needs and which
qualifiers apply. At runtime, Micronaut uses these definitions to create beans
and resolve their dependencies, avoiding reflective discovery of that metadata.

This does not mean every dependency problem is a compile error. A missing bean
or an ambiguous qualifier can still cause an error when Micronaut tries to
create the bean at runtime.

Scala also has different rules for Java annotation arguments. See
<<annotations, Annotations>> when adapting an example from the Java guide.

== Dependency injection

A *bean* is an object managed by Micronaut. Start by defining a trait for a
dependency:

snippet::io.micronaut.docs.di.Vehicle[source=main,language=scala,tags=interface]

Annotate each implementation with `@Singleton` to make it a bean. Here,
`@Named` distinguishes two implementations of the same trait:

snippet::io.micronaut.docs.di.Vehicle[source=main,language=scala,tags=implementations]

Declare the dependency as a constructor parameter. A *qualifier*, such as
`@Named`, selects an implementation when several beans have the required type:

snippet::io.micronaut.docs.di.Vehicle[source=main,language=scala,tags=injection]

`ApplicationContext.run().getBean(classOf[Vehicle])` creates a `Vehicle` with
`V8Engine` supplied. If no matching engine bean is available, creating the
`Vehicle` fails at runtime.

TIP: Prefer constructor injection in Scala. Dependencies are available as soon
as the class is constructed, and a unit test can supply them directly with
`new`. Micronaut also supports field and setter injection with `@Inject`.

=== Scopes

A *scope* controls a bean's lifetime. `@Singleton` shares one instance within
an application context. `@Prototype` creates a new instance for each injection
or lookup:

snippet::io.micronaut.docs.di.Vehicle[source=main,language=scala,tags=prototype]

Other Micronaut scopes include `@Context`, `@Refreshable` and request scope in
server applications.

== Configuration properties

`@ConfigurationProperties` binds a class to a section of application
configuration. The resulting object is a bean that other beans can inject:

snippet::io.micronaut.docs.config.EngineConfiguration[source=main,language=scala,tags=clazz]

Set `engine.manufacturer` to `Ford` and `engine.cylinders` to a list to supply
the corresponding constructor values. `nickname` is optional: when its
configuration property is absent, it binds to `None`. The `List[Int]` parameter
receives a Scala list with each element converted to an integer.

These conversions require `micronaut-runtime-scala` on the runtime classpath.
Scala `Seq`, `Set` and `Map` are also supported. A required parameter without
a value or a default prevents the configuration bean from being created.

== Bean introspection

`@Introspected` asks Micronaut to generate metadata for constructing a type and
accessing its properties. Validation, data binding and serialization can use
this metadata without discovering properties through reflection:

snippet::io.micronaut.docs.introspection.Book[source=main,language=scala,tags=clazz]

`BeanIntrospection.getIntrospection(classOf[Book])` exposes `title` and `pages`
as properties and can instantiate `Book` from their values. The case class's
constructor parameters supply its properties, and its generated accessors
supply the getters.

Ordinary classes can also be introspected. The plugin recognises Scala `val`
and `var` accessors as well as getter and setter pairs. A `val` is read-only;
a `var` can also be written through its setter.

== Serialization

https://micronaut-projects.github.io/micronaut-serde/latest/guide/[Micronaut Serialization]
uses generated introspections to read and write objects. Mark a case class
with `@Serdeable` to enable both directions:

snippet::io.micronaut.docs.serialization.Order[source=main,language=scala,tags=clazz]

An injected `ObjectMapper` writes this example as
`{"id":"A-1","quantity":3}` and reads it back through the case class constructor.
Add `io.micronaut.serde:micronaut-serde-jackson` to use the Jackson-based
implementation.

For properties declared as Scala collections, `Option` or Scala 3 enums, also
include `micronaut-runtime-scala`. See <<serialization, Serialization>> for
JSON examples and the handling of missing optional fields.

== Around advice

*Aspect-oriented programming* (AOP) lets an interceptor add behaviour around a
method call. Common uses include logging, retries and transactions. Micronaut
generates the proxy classes during compilation.

To define custom around advice, first declare an annotation marked with
`@Around`:

snippet::io.micronaut.docs.aop.OrderService[source=main,language=scala,tags=annotation]

Then bind an interceptor to the annotation. The interceptor receives the call
and invokes `proceed()` to continue to the original method:

snippet::io.micronaut.docs.aop.OrderService[source=main,language=scala,tags=interceptor]

Apply the annotation to the methods you want to intercept, or to a class to
advise its eligible methods:

snippet::io.micronaut.docs.aop.OrderService[source=main,language=scala,tags=bean]

Calling `place` runs the interceptor and returns `ordered a book`. Calling
`quote` does not run the interceptor.

The annotation extends `java.lang.annotation.Annotation` because
`@InterceptorBean` accepts a `classOf[...]` argument with that bound. See
<<annotations, Annotations>> for details.

The generated proxy extends the advised class and overrides its advised
methods. A `final` class or advised method therefore causes a compilation error.

== Introduction advice

*Introduction advice* supplies the implementation of abstract methods. This
is how Micronaut implements declarative clients and repositories.

The interceptor uses the invocation context to decide how to answer each call:

snippet::io.micronaut.docs.introduction.GreeterClient[source=main,language=scala,tags=interceptor]

An annotation marked with `@Introduction` enables the advice. `@Type` identifies
the interceptor:

snippet::io.micronaut.docs.introduction.GreeterClient[source=main,language=scala,tags=annotation]

Apply the annotation to a trait or abstract class:

snippet::io.micronaut.docs.introduction.GreeterClient[source=main,language=scala,tags=abstract]

`getBean(classOf[Greeter]).greet("Scala")` returns `greet(Scala)`, the value
supplied by the interceptor. An abstract class can also have constructor
dependencies and concrete methods; those methods keep their implementation.

== Data access

Micronaut Data uses introduction advice to implement repositories. An entity
can be a case class whose constructor parameters describe the mapped properties:

snippet::io.micronaut.docs.data.Book[project=test-suite-scala-data,source=main,language=scala,tags=clazz]

In this example, `@Id` marks the identifier and `@GeneratedValue` asks the
database to generate it.

Declare a repository as a trait extending `CrudRepository`. Methods such as
`findByTitle` describe queries through their names:

snippet::io.micronaut.docs.data.BookRepository[project=test-suite-scala-data,source=main,language=scala,tags=clazz]

During compilation, Micronaut Data processes the entity and repository and
records the SQL and query metadata. Micronaut generates a repository proxy
whose interceptors execute those queries at runtime. You inject
`BookRepository` without writing an implementation yourself.

Scala collections can be used for query results, but optional single results
currently need `java.util.Optional`. See <<data, Micronaut Data>> for the
processor dependency, supported signatures and a database configuration.

The examples in this chapter are compiled and exercised in `test-suite-scala`
and `test-suite-scala-data`.
